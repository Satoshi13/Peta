# Boards 実装報告

作業日: 2026-10-13。`docs/archive/prompts/codex-boards-backend-prompt.md` の全文、および「1. 共通ルール」の文書・core / app / JS の指定ファイルを全て読んだ後、Step 1〜6 の順で実装した。`boards-plan.md` と `decisions.md` の決定を踏まえ、相違は依頼書と現行コードを優先した。

## 作ったもの

- **V15 / core**: `boards` / `board_items` / `board_rules`、初期台紙2枚、保存・無料上書き・名前変更・削除。白紙は所持数−保存数。名前は1〜24文字。0枚・白紙なし・不正値を拒否する。
- **購入**: Rust の Tools に Board ×1 / 12 Scraps。所持上限12、無料 Developer も上限共通。受領書で同一 request ID の再送を二重購入にしない。残高不足・上限・破損した所持数で残高と台紙を変更しない。
- **切り替え**: 対象を全部剥がして参照の配置を復元。held 以外と他画面（Stored 含む）を理由つきで飛ばす。配置・Undo を1トランザクションで確定し、失敗時は元に戻る。Undo は1枠、復元時の手放したもの・他画面のものも飛ばす。印刷列・今日の1枚・Scraps・タグは変えない。
- **画面の記憶**: 未接続の配置を primary に寄せる fallback を廃止。`placements` の画面 ID と割合を保持し、再接続時に戻す。Stored の Bring them here は ID のみ移して幾何情報・時刻を維持する。
- **ネイティブ境界 / UI**: 依頼の12コマンド、接続画面の名前・種類・縦横比・状態を返す。変更は placements-changed / boards-changed で反映。見本を廃止し、実ステッカーの縮小画像・配置・z と、不在 / 他画面の点線の影を描く。保存等のダイアログ、在庫、Undo、短い英語のエラーを実コマンドにつないだ。
- **Auto**: core の純粋判定、永続実行日、時間帯・日またぎ・Wi‑Fi の開始・一覧の優先順位。勝者の配置・Undo と全候補の時間帯の実行日を同じトランザクションで確定する。失敗は開始を消費せず再試行できる。有効ルールがある間だけ1分ごとに確認し、起動・復帰・画面変更・ルール変更でも確認する。
- **macOS**: CoreWLAN と CLLocationManager、保持した delegate と NSWorkspace の復帰 observer。起動時の delegate 登録では許可を要求せず、初回 Place の Continue からだけ要求する。拒否でも保存可、一覧 / ダイアログで Location is off for Peta を表示する。Info.plist に理由を追加。観測 SSID は判定中のメモリだけで、位置そのものは取得しない。DB / ログ / 通信に観測 SSID を書かず、ユーザーが入力したルールの名前だけを保存する。
- **メニューバー / 公開**: 接続画面別の Boards、2画面以上の見出し、現在一致のチェック、Undo、メイン画面の保存ダイアログ、Open Boards。native の変更で再構築する。通常版にも Boards と Board ×1 を表示する。

## 判断・依頼書との違い

1. `board_items` の幾何値と z は既存の配置と同様に **NOT NULL** とした。V1〜V14 の SQL は変更せず、V15 の保持移行をテストした。`boards.undo` は操作があったときだけ作り、復元で削除する。
2. 時間帯は **開始を含み終了を含まない**。日またぎの朝は前日の開始日・曜日を使う。再起動でも同じ時間帯を繰り返さない。場所は依頼の明示どおり、起動時の一致を新しい開始に数える。
3. 同時に当てはまった下位のルールも、その開始を消費する。次の分に下位が勝者を上書きするのを防ぐため。複数画面は画面 ID 順に1トランザクションで処理し、指定どおり1枠の Undo には最後の画面が残る。
4. **ルール保存・再有効化は新しい開始として再準備**する。並べ替え・手動切り替え・Undo は再準備しない。新しい設定を現在の窓から使えるようにするため。README / decisions に明記した。
5. Wi‑Fi の読み取り不能 / 許可オフは切断と区別し、実行済み状態を保持する。同じ接続のままモニターを外して戻しても再実行しない。未接続時に新しく始まった条件は、接続後の確認まで待つ。
6. 接続状態の公開と Auto の DB 確定を短い排他で保護する。Store と Layers の内部ロックを入れ子にせず、native UI 操作前に保護を解放する。許可説明の完了記録は main-thread dispatch の成功後に書く。
7. 布ボード・カード・ダイアログのデザインは保持した。必要な UI 変更は実画像、実数・空表示、Stored の取り込み、許可オフの説明、見本注記の除去。見本の配置を使った切り替え演出は、コマンド成功後の結果表示に置き換えた。
8. 既存の Scraps 同時再送テストは、接続初期化の失敗で片方が barrier を待ち続ける可能性があった。接続を先に準備し、購入トランザクションの同時実行を維持した。製品の Scraps ルールは Board 追加以外に変更していない。

## 残る弱点とオーナーの実機確認

画面 ID は既存の名前ベース（`assign_display_ids` の TODO）で、OS による改名や同型2台の列挙順変更には弱い。未接続の画面表示は ID と既定の縦横比を使い、接続時に実値に戻る。Bring them here を逃げ道にした。

場所の実行済み状態と待っている知らせはメモリのみ。場所は起動で新しい開始、時間帯の実行日は DB に残る。1分間の間に切断・再接続が完了すると中間の変化は観測できない。通知待ちはアプリ終了で消える。複数画面を同時に Auto 適用した場合も Undo は1画面分だけ。

ブラウザー検証はコマンド境界を隔離しており、**CoreWLAN / macOS の許可ダイアログ / スリープ / 実モニター / native メニューを実機で完了確認したものではない**。以下は [macOS チェックリスト](../../port-spec/macos-checklist.md) の項目として残した。

- 2画面のつなぎ外し・戻し・名前変更と Bring them here。
- スリープ復帰時の窓内1回実行、日またぎ、手動変更・Undo・再起動。
- Wi‑Fi 切り替え、初回 Continue、許可 / 拒否 / システム全体オフ、再起動後の設定変更。
- 窓が閉じているときの知らせ、メニューのチェック・Undo・保存ルート。
- 署名した通常版 .app の Info.plist と位置情報許可の実挙動。
