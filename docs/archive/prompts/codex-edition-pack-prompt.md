# Codex への依頼: Pack を「版を刷る本物のガチャ」にする

**使い方**: この文書の全文を Codex に渡す。**実装の指示**(Rust・JS)で、画像制作・見た目のデザインではない。作業は **Step 順**。各 Step の終わりに `cargo test --manifest-path src-tauri/Cargo.toml --workspace` と `npm test` を通す。

> 日本語で指示。コード中のコメントと UI の文言は、既存に合わせて**英語**。説明文書は日本語。

**前提**: [`codex-uniqueness-prompt.md`](codex-uniqueness-prompt.md) が**先に終わっていること**(本物 / 複製、作者の署名、移動の記録、`Referee` の口)。この依頼は、その形を使う。

**背景(決定済み、`docs/decisions.md` 2026-10-11「Pack は版を刷る本物のガチャ」)**:

- **Pack は、作り手が版を刷る本物のガチャ**。作り手が、どのステッカーを**何枚**(版)入れるかを決める。コピーに番号(`#3/10`)が付き、刷った数は**署名で固定**され、あとから増やせない。
- 出る割合は、**残りの枚数の比**。**重複なしで引き**、売り切れる。いまの「重み(1 / 2 / 4 / 8 / 16)」は、**版の枚数に置き換える**。
- 封をすると、ステッカーは**コピーされずパックの中に移る**(本物は移動する)。
- 景品は、ステッカーのほかに**素材とリンクタグ**も入れられる(売り手の手持ちから、パックの中に移る)。素材・タグは分解して Scraps に戻せる。**ステッカーは分解できない**。
- 自分のパックを自分で開けて増やす穴(いまの「My shelf」)は、この仕様で塞ぐ。

---

# 0. 範囲

## やること

1. パックの形式 **`PETAPACK` v2**(版の枚数・景品・番号を、署名の対象にする)。v1(重み)のファイルと公式パックは、**いままでどおり**動く。
2. DB の拡張(**V13**)。引く処理の置き換え(重複なしの一様な抽選)。
3. 封をする処理(Studio の「Seal」)を、**刷る(press)**処理にする: 版の発行、ステッカー・素材・リンクタグの移動。
4. 開ける処理: ステッカー(番号つきの版)・素材・リンクタグの受け取り。**自分のパックは開けられない**。
5. Studio の**機能に必要な最小限の変更**(§7)。見た目は、いまの構造と部品に合わせる。**視覚的な仕上げは別担当**。
6. ドキュメント・テスト・報告。

## やらないこと

- **値段・Scraps の支払い・売り手の取り分**。Scraps の経済は、**このあとの別の作業**。ユーザーのパックは、いまは「Free」のまま。値段の定数だけ、1か所に**使わない形で**置く。
- サーバー(友達・受信箱・審判役)。**ただし口を作る**(§5)。
- 二次流通(開けたステッカーを自分のパックに入れ直す)の専用の画面。`codex-uniqueness-prompt.md` の「移動」で、**コード上は可能**にしておくが、UI は作らない。
- 封をしたままのパックの売買・贈与(**しない**。決定済み: 売買は転売にしかならない)。

# 2. Step 1: `PETAPACK` v2 のデータ形式

ヘッダ(署名の対象)を次のように拡張する。v1 の項目(`pack_id`、`version`、`title`、`author`、`pouch`、`made_at`、`signer`、`cover`、`deco`、`blurb`、`layout`)は、そのまま。

- `items` を **デザイン**の並びにする(v1 の `Item` に、次を足した形):
  - `copies: u32` — このデザインを何枚入れるか(**1 以上、`MAX_COPIES_PER_DESIGN` 以下**。定数1つ。**いまは 30**)。
  - v1 の `weight` は、v2 では**持たない**。
- `prizes: Vec<Prize>`:
  - `{ kind: "material", material_id, count }`(素材のシート。`count` は 1 以上)
  - `{ kind: "tag", count }`(リンクタグ。`count` は 1 以上)
  - 景品の合計の上限は定数1つ(いまは 10 個)。
- **スロット(1回で1つ引かれる単位)**: デザインごとの `copies` 個 + 景品の個数。**合計の上限は 1パックあたり 200**(定数1つ)。
- **版の番号**: デザインごとに `edition_no` は 1〜`copies`。**各コピーの番号は、スロットごとに固定**で、ヘッダに含める必要はない(デザインと `copies` から決まる。引くときに、残っている番号の中から選ぶ)。
- 署名は、ヘッダ全体(`copies`・`prizes` を含む)にかかる。**値を書き換えたら署名が合わない**ことを、テストで確かめる。
- `validate`: `copies` の範囲、`prizes` の種類・個数・上限、スロット数の上限、`material_id` が既知か。
- **v1 のファイルは、v1 のまま読める・開けられる**(重みで引く)。`pack_distributions` などの既存の記録は変えない。新しく作るのは常に v2。

# 3. Step 2: DB(V13)と引く処理

## 3.1 DB

- `signed_pack_items` に `edition_no INTEGER`、`edition_total INTEGER`、`kind TEXT NOT NULL DEFAULT 'sticker'`(`'sticker'` / `'material'` / `'tag'`)、`prize_ref TEXT`(素材のID)を足す。v1 の既存行は、`kind = 'sticker'`、`edition_*` は NULL。
- v2 のパックは、**スロット1つにつき `pack_items` を1行**入れる(いまの「1行 = 開けると1回」の流儀に合う)。デザインの画像は、デザインごとに**1回だけ**ファイルに保存して、コピーの行から参照する(**画像を枚数ぶん複製しない**)。
- `pack_item_weights` は、v1 のためにそのまま残す。v2 では使わない。

## 3.2 引く処理

- `creator_pack::pick` を拡張する: **v2 のパックは、残っているスロット全体から、一様に1つ**選ぶ(重みなし)。乱数は**引数で渡せる**まま(テストで固定できるように)。**重複なし**(開けたスロットは、もう出ない)。**v1 のパックは、これまでどおり重みで引く**。
- `pick_bonus`(無料開封)も同様に、v2 に対応する。
- `peek`(パックの上の見え方)は、v2 では、残っているデザインの絵を返す(景品の素材・タグは絵がないので、含めない、または汎用の絵にする。UI の都合で決めてよいが、**中身を教えない**: 一覧には出さず、上位の数枚だけ)。
- 「**残り N 個**」(`remaining`)は、スロット数で数える(いまと同じ意味)。

# 4. Step 3: 刷る(press)— Studio の「Seal」

`creator_pack_save` / `creator_pack_shelve` の `items` を、`{ sticker_id, name, copies }`(`weight` をやめる)と、`prizes` に変える。

## 4.1 刷るときの規則(**1つのトランザクション**。途中の失敗は全部元に戻る)

| 対象 | 規則 |
|---|---|
| **自分が作った本物**(`lineage = 'real'`、作者が自分) | `copies` 枚の版を**刷る**。**元の原本は Collection に残る**(原版)が、`pressed` の印を付け、**同じデザインを、もう一度刷ることはできない**(`Error::Invalid("already_pressed")`)。1つのデザインにつき、刷る機会は**1回**。 |
| **受け取った本物**(他人が作者の原本・版) | `copies` は **1 だけ**。**パックの中に移る**(Collection から消える。`transfers` に `release`)。他人の作品の版を勝手に増やせない。 |
| **複製**(`lineage = 'copy'`) | **選べない**(`copies_stay_home`)。 |
| **景品の素材** | 売り手の素材の在庫から、`count` 個を**移す**(`consume_material`)。足りなければ拒否(`not_enough_material`)。 |
| **景品のリンクタグ** | 売り手のリンクタグの在庫(`available`)から `count` 個を**移す**。足りなければ拒否。**ステッカーに付けているタグは、景品にできない**(まず外す)。 |

- 原本の複製(飾り用)は、刷っても**残る**(原本は手元に残るので)。**受け取った本物がパックに移るとき**は、その複製を削除する(`codex-uniqueness-prompt.md` §3.4)。
- 刷った記録は、`packs_made`(いまの `record_made`)に残す。**同じタイトルで刷り直す**(version が上がる)ときは、**新しい版を足せない**(`copies` を増やす・景品を足すのは拒否)。**売り切れてから、新しいパック(別のタイトル・別のデザイン)を作る**。補充は「新しいデザインを新しいパックで出す」。
- 署名は、これまでどおり作り手の端末鍵。

## 4.2 保存先

- **My shelf**: 自分の棚に、**自分のパックの出品(見本)**として置く。**自分では開けられない**(§5)。「あと N 個」の在庫表示だけ。
- **File to share**: 署名つきのファイルを書き出す(いまと同じ。ダイアログでキャンセルしたら、何も刷らない)。
- どちらの場合も、**刷った(移動した)内容は、保存が成功したときにだけ確定**する(いまの Studio の「封をすることが本当の作成」と同じ。失敗したら、元に戻る)。

# 5. Step 4: 開ける(open)と、審判の口

## 5.1 開けるとき

- ステッカー(番号つきの版)が出たら、**新しい本物**として Collection に入る: `source_type = Pack`、`edition_number = edition_no`、`edition_total`、作者は作り手、`lineage = 'real'`。作者の署名と、`transfers` の連鎖(`create`(作り手)→ `release`(作り手が刷った)→ `claim`(開けた人))を持つ。来歴は `PackOpened`。
- 素材が出たら、**素材の在庫に加える**(`add_material`)。リンクタグが出たら、**リンクタグの在庫に加える**(`link_tag_add_stock`)。いずれも、開封の演出の結果に、種類と名前を返す(UI の都合で、素材・タグ用の演出は、いまのステッカーの演出を流用してよい。**新しい演出は作らない**)。
- 引いたスロットは、**そのパックの中で消える**(重複なし)。

## 5.2 自分のパックは開けられない

- 作り手の端末(パックの署名鍵 = 自分の鍵)は、**そのパックを開けられない**(`Error::Invalid("your_own_pack")`)。画面では「Your own pack: friends open it」と出す。
- 自分の棚の自分のパックは、**在庫(あと N 個)と見本の表示だけ**。「Open」のボタンは出さない。
- **理由**: 自分で開けて、自分の版を増やす抜け道を塞ぐため(決定済み)。

## 5.3 審判の口(いまは何もしない)

`codex-uniqueness-prompt.md` §6 の `Referee` に、**スロットの獲得**を足す。

```rust
pub trait Referee { /* ...register / release / claim... */ fn claim_slot(&self, pack_id: &str, slot: u32, claimer_key: &str) -> Result<()>; }
```

- 開けるとき、引いたスロットを `claim_slot` で申告する。`NoReferee` は、何も拒否しない。**拒否されたら、開ける処理全体を元に戻す**。
- **審判がない間の限界を、はっきり書く**(README・報告): **同じパックのファイルを、複数の友達が、それぞれ別に開けると、同じ番号の版が、複数の人の手元に現れる**(ファイルがコピーされているため)。この間、受け取った版の画面には、**「Edition numbers are not checked by a server yet」**と読める小さな注記(開発者版だけでもよい)を、データとして持たせる(`stickers.verified = 0` のような既存の仕組みを使う)。サーバーが入ったら、`claim_slot` が拒否する。

# 6. 旧「確率(重み)」の扱い

- Studio の「Edit chances…」(重みの上げ下げ)は、**「Copies」(デザインごとの枚数)に置き換える**(§7)。v1 の重みのコードは、v1 のパックを開けるために**残す**(UI からは、新しく作れない)。
- 画面の「確率(%)」は、**残りの枚数 ÷ 残りの全スロット数**から計算する。**表示のみ**で、保存しない。`stOdds` を、枚数から計算する形に置き換える(テストも)。
- `docs/decisions.md` の Studio の行(「確率は…Edit chances…」)に、「**版の枚数に置き換え済み**」と注記する。

# 7. Step 5: Studio の最小限の変更

**構造は、いまの「Gather / Dress / Seal」の3工程と、左のプレビュー・右のパネル・フッターを保つ。見た目の仕上げは別担当。文言は英語。**

- **Gather**: ステッカーを選ぶ(いまのまま)。選ぶ一覧は、**自分の本物(原本・受け取った本物)だけ**。**複製は出さない**。「Equal chances / Edit chances…」の行を、**「Copies」の行**に変える。
- **Copies パネル**(いまの Chances パネルの置き換え): 選んだデザインごとに、**枚数のステッパー**(1〜`MAX_COPIES_PER_DESIGN`)。**自分が作った本物だけ**ステッパーが効き、**受け取った本物は 1 に固定**(理由を一言: 「Made by someone else: one copy」)。**すでに刷ったデザイン**(`pressed`)は選べない(理由を表示)。合計のスロット数(上限 200)と、各デザインの割合(%)を、表示だけ。
- **景品(Prizes)**: 素材(在庫のある種類を選び、個数)、リンクタグ(在庫の範囲で個数)。在庫を超えて選べない。**Gather の下か、Copies パネルの中**(置き場所は、既存の構造に合わせて決めてよい)。
- **Dress**: いまのまま(包装・名前・Layout・カバー・アクセント)。**カバーに選べるのは、パックに入れた自分のデザインだけ**(いまと同じ)。
- **Seal**: 要約に「N designs · M copies · P prizes」を足す。**「これらは Collection / 在庫から出てパックの中に移る」**と、確定ボタンの近くに明記する(いまの「It cannot be edited afterward」の隣)。保存先(My shelf / File to share)は、いまのまま。
- 開封の画面(Packs): 自分のパックには「Open」を出さない。残り枚数の表示。
- `tests/studio*.test.mjs`: 新しい引数の形(`copies`・`prizes`)、複製が選べないこと、受け取った本物の枚数が1に固定されること、確率の表示が「残り枚数の比」であること、を確かめる。**既存のテストのうち、重みに関するものは、新しい形に合わせて書き換える**(意味が変わるので)。

# 8. テスト

**core(Rust)**:
- V12 → V13 のマイグレーション。v1 のパックのデータが保たれる。
- v2 のヘッダの署名: `copies`・`prizes`・番号に関わる値を書き換えると、署名が合わない。範囲外(`copies` 0 / 31、スロット 201、景品 11 個、未知の素材)は拒否。
- 刷る: 自分の本物は `copies` 枚の版が刷られる、原本は残り `pressed` になる、**同じデザインを2回刷ると拒否**、受け取った本物は `copies = 1` だけでパックに移り Collection から消える、複製は拒否、素材・リンクタグが売り手の在庫から減る、在庫不足は拒否、**途中の失敗で全部元に戻る**(ステッカー・素材・タグのどれも減らない)。
- 引く: 一様・重複なし。スロット数ちょうどで売り切れる。乱数を固定して再現できる。デザインごとの番号が 1〜`copies` の範囲で、重ならない。
- 開ける: ステッカーは番号つきの本物として入る(連鎖の検証が通る)、素材は在庫に加わる、リンクタグは在庫に加わる、**自分のパックは `your_own_pack` で拒否**。
- v1: 重みのパック・公式パック・Welcome・無料開封が、**いままでどおり**動く(既存のテストが通る)。
- `Referee`: `NoReferee` が通す、`claim_slot` を拒否する偽物で、開ける処理が元に戻る。

**JS**: §7 のテスト。

# 9. 受け入れ条件

- [ ] Studio で、デザインごとに枚数を決めて、素材・リンクタグの景品を足し、封をできる(My shelf と File to share のどちらでも)。
- [ ] 封をすると、受け取った本物と景品が手元から出る(原本は残り、`pressed` になる)。同じデザインは、もう刷れない。
- [ ] 友達の端末(別のデータフォルダ)でパックを開くと、番号つきの版・素材・リンクタグが出て、重複なしで売り切れる。
- [ ] 自分のパックは、自分では開けられない。
- [ ] v1 のパック・公式パックが、いままでどおり動く。
- [ ] `cargo test --workspace` と `npm test` が通る。`docs/decisions.md` と `README.md` が更新されている。
- [ ] 報告 `docs/archive/reports/edition-pack-report.md` に、**作ったもの・守れないこと(審判がない間、同じファイルを複数人が開くと、同じ番号が複数現れる)・実機で確認する項目**を、日本語で書く。

**実機でしか確認できないこと**(オーナーがやる): 2つのインスタンスでの、刷る → ファイルを渡す → 開ける、の一連の流れ。Studio の操作感。
