## 1. デスクトップ上のホログラムの反射を、カーソルに追従させる

### 欲しい動き
- ホログラム系(今は `holographic`。**ゴールドは素材として実装された時に同じ仕組みに乗れるよう、「反射する素材の一覧」を1か所の定数にまとめる**)のステッカーで、**反射の帯がカーソルとの相対位置で滑る**。画面のどこにカーソルがあっても(ステッカーに触れていなくても)反応する。
- **やらないこと(明示)**: 3D の傾き(rotateX/rotateY)、スペキュラの丸い光、影の変化、拡大。ステッカーの `transform` は一切いじらない。変えるのは反射の帯の位置・角度だけ(既存の `.sticker[data-material="holographic"] .body::after` が使う `--sx / --sy / --sa`)。
- カーソルが画面にない/まだ動いていないときは、**今の見た目(位置と回転から決まる静止の反射。`setSheen`)にそのままフォールバック**する。見た目が急に変わらないこと。
- カーソルが動いたら滑らかに追従し(目標値へ補間)、止まったら補間が収束した時点で `requestAnimationFrame` を止める。

### 仕組み(重要)
デスクトップ層は、Resting のときクリックを通す(`set_ignore_cursor_events(true)`)ため、JS の `pointermove` は届かない。**Rust 側でグローバルのカーソル位置を取得して、層へ送る**。

1. `src-tauri/src/platform/` に、カーソルの画面座標を返す関数を追加する(macOS: `NSEvent.mouseLocation`。メインディスプレイ左下原点なので、上原点・各層ウィンドウ座標へ変換する。複数ディスプレイ・Retina に注意)。`windows.rs` はスタブ(`None`)。
2. 層ごと(`layers.rs` の各レイヤー)に、**その層ウィンドウ内の座標**へ変換して、イベント(例: `cursor-reflect`、ペイロードは `{ x, y }` と、層の外にあるかのフラグ)で送る。座標が前回と同じなら送らない。
3. **取得は必要なときだけ**: 層(JS)が「反射する素材のステッカーが画面内に1枚以上ある」ことを Rust に伝える(例: `set_reflection_active(bool)` コマンド)。1枚もなければタイマーは止める。動作中の間隔は 30fps 程度(約 33ms)。アプリ終了・ディスプレイ再構成(`Re-sync Displays`)で止まる/作り直されること。
4. 層側(`src/main.js`)は、受け取った座標から各ステッカーの `--sx / --sy / --sa` を計算する。ステッカー中心からカーソルへの向きと距離で帯が動く(距離は `clamp`。近いほど帯がはっきり、遠いほど控えめ、は任意)。Edit Mode 中は層が自前の `pointermove` を受けられるが、**同じ計算式を使い、見た目が途切れないこと**。
5. 「Reduce motion」のときは、**追従をやめて今の静止表現に固定**する(Rust のタイマーも止める)。

### 受け入れ条件
- ホロのステッカーが無い/Reduce motion のとき、Rust 側のカーソル取得タイマーは動いていない(ログかカウンタで確認できる形にする)。
- 複数ディスプレイで、それぞれの層のステッカーが自分の座標系で正しく反応する。
- 通常の素材(Matte/Kraft)の見た目と挙動は変わらない。
- `tests/placement.test.mjs` などの既存テストが通る。座標変換(画面座標→層座標、上下反転)は**純関数に切り出して `tests/` にテストを追加**する。

### macos-checklist に追記する項目
- ホロのステッカーにカーソルを近づける/離すと帯が滑る(傾きや影の変化は無い)。
- 2枚目のディスプレイでも同様。
- ホロを剥がして0枚にすると、反射のための CPU 使用がアイドルに戻る(アクティビティモニタ)。
- Reduce motion で追従しない。

## 2. 触覚フィードバック(貼る・剥がす・封蝋を割る)

### 欲しい動き
次の3つのときだけ、**トラックパッドの触覚を1回**。それ以外(ドラッグ中、ホバー、ボタン操作など)では鳴らさない。

| いつ | どこ | パターン案 |
|---|---|---|
| ステッカーを貼った瞬間(Print → Grab → Paste の「ペタッ」、編集モードで貼り直した瞬間) | `src/print.js` の `pata()`、`src/main.js` の貼り直し | `NSHapticFeedbackPatternLevelChange`(2) |
| 剥がしが確定した瞬間(Option+引き離しで外れる、Book の Peel off など `peel_sticker` が成功したとき) | `src/main.js` の `peelOff` | `NSHapticFeedbackPatternGeneric`(0) |
| Gift の封蝋を割った瞬間 | `src/app/js/ceremony.js` の `crack` | `NSHapticFeedbackPatternGeneric`(0) |

パターンは実機で一番自然なものに差し替えてよい(迷ったら上の案)。

### 実装
- Rust: `platform::haptic(kind)`。macOS は `NSHapticFeedbackManager.defaultPerformer` の `performFeedbackPattern:performanceTime:`(`performanceTime` は Default)を、既存の `msg_send!` 流儀で呼ぶ(`macos.rs` 参照)。メインスレッドで呼ぶ。`windows.rs` は何もしない。
- Tauri コマンド `haptic_tap`(引数: `"paste" | "peel" | "seal"`)を追加し、**`src-tauri/capabilities/layer.json` と `app.json` の両方**で許可する。
- JS: 呼び出しを1つのヘルパー(例: `Haptic.tap(kind)`)にまとめ、`Snd` のすぐ横に置く。**同じ操作で2回呼ばない**(貼る処理が複数経路から呼ばれても1回)。
- 設定: `Settings` に「Haptics」スイッチを **Sounds / Reduce motion と並べて**追加(既定オン)。`peta.preferences` に保存し、層にも `preferences-changed` で伝える。Reduce motion とは独立(触覚は動きではない)。
- 触覚が使えない環境(トラックパッド以外、権限なし)でも、**エラーにせず何も起きない**こと。

### macos-checklist に追記する項目
- 貼る/剥がす/封蝋を割る、の3つで1回ずつ触覚がある(Force Touch トラックパッド)。
- Settings の Haptics をオフにすると鳴らない。
- ドラッグ中・ホバーでは鳴らない。

## 3. 次の封筒までのカウントダウン(ローカル 0 時)

### 欲しい動き
Today ページに、**「Next envelope in HH:MM:SS」**を表示する(参考: `upgrade-preview.html` の提案2、紙のチケット風の小さな札。数字は `Special Elite` の等幅)。

- 表示する条件: **今日の素材を開封した後**(封筒がまだ未開封のときは出さない。封筒そのものが今日の主役)。「今日の枠」の使用状況には依存しない(1日に何枚でも作れるため)。
- 時刻は**端末のローカル時間で、次のローカル 0:00 まで**。1秒ごとに更新。ページが見えていない間(別ページ・ウィンドウが閉じている)は更新を止める。
- 0:00 に達したら、既存の日付切り替え検知(約30秒おき)を**待たず即座に同じ更新処理を呼ぶ**(新しい封筒の抽選・スロットのリセット)。更新後は封筒の表示に戻り、カウントダウンは消える。
- 開発用の「Next Day (+1 day)」の後でも壊れないこと(時刻は実時間のローカル 0:00 基準。`daily.date` は Rust 側の日付なので、そちらは触らない)。
- アクセシビリティ: 毎秒の読み上げを避ける(`aria-live` を付けない)。`aria-label` は分単位で更新する(例: 「Next envelope in 13 hours 41 minutes」)。
- 色・書体は既存トークン(`--ink` / `--muted`、`Special Elite`)。新しい素材画像は使わない。

実装場所の目安: `src/app/js/shared.js`(Today ページ)、`src/app/js/today.js`、状態は `src/app/js/bridge.js` の `S`。

### 受け入れ条件
- 開封後の Today に札が出て、秒が進む。未開封では出ない。
- ページを離れるとタイマーが止まる(`setInterval` が残らない)。
- 時刻計算(次の 0:00 までの秒数、日付境界・夏時間の日)は**純関数にして `tests/` にテストを追加**する。

## 4. Book: 通常(List)モードとカレンダーモード

### 現状
`src/app/js/book.js`: `Pages.book.build()` が月タブ(`nav.months`)と、`h2.month-title`(「October 2026」)・件数を出し、**月ごと**に並べている。データは `S.lib`(`e.date` = 貼った日。`bridge.js` の `reload`)と、Rust の `book_index` / `book_page(year, month)`。詳細パネル(`detail`)・裏返し・Peel / Gift / Stick as today's Peta は**そのまま再利用**する。

### 欲しいもの
Book に **List / Calendar の表示切り替え**(ページ見出しの横にセグメント。選択は `peta.preferences` に保存。既定は List)。

#### List(通常モード)
- **月タブ・年月の見出し・月ごとの件数は出さない**(添付画像の「Oct」タブと「October 2026」を無くす)。
- 全期間を**新しい順**にタイル表示(同日は新しく作られた順)。件数は「N stickers」のように控えめに1つだけ。
- 並べ替え・絞り込みを控えめに付けてよい:
  - Sort: `Newest`(既定)/ `Oldest` / `Material`
  - Filter(チップ): `All` / `On desktop` / `Gifts`(受け取ったもの)/ 素材別(持っている素材だけ)
  - 絞り込み結果が 0 件のときは、既存の空表示の流儀で短い文言を出す。
- 多数のステッカー(数百)でも重くならないよう、画像は既存の `resOf` のキャッシュを使い、**表示領域に入ってから生成**する(`IntersectionObserver` など)。

#### Calendar(カレンダーモード)
参考: `upgrade-preview.html` の提案3(見た目は紙の台帳。日付の数字は手書き書体 `Klee One`)。

- 月の切り替え: 「前の月 / 次の月」と、月見出し(「October 2026」)、「N days stuck · M Petas」。月移動は既存の `turn` のめくり演出を再利用(Reduce motion で省略)。ステッカーがある月だけでなく、**今月までの連続した月**を移動できる(空の月も開ける)。未来の月へは行けない。
- 曜日は7列。週の始まりはロケールに従う(分からなければ日曜)。
- 各日のセル:
  - **貼った日**: その日のステッカー(1日に複数あれば、最新を一番上に。右上に `×N`)。傾きは日付から決める決定的な値(−6°〜+6°。再描画でも変わらない)。ホバーで少し持ち上がり、`Oct 2 · 名前` のツールチップ。クリックで既存の詳細パネルを開く(複数ある日は、その日のステッカー一覧を詳細内で選べるようにするか、最新を開いて他は小さなサムネで切り替える。実装しやすい方でよい)。
  - **休んだ日**(過去でステッカー無し): 薄い枠と小さな `rest`。責める表現にしない。
  - **今日**(ステッカー無しのとき): 脈打つ破線の円に `+`。クリックで Today ページへ移動する(**新しいルールは作らない**。今日の作成フローは既存のまま)。
  - **未来の日**: 日付の数字だけ、薄く。
- 月が**すべての日で1枚以上**埋まった過去の月には、ホロの「30/30 COMPLETE」スタンプ(CSS で作る。新素材なし)を見出しの横に出す。表示したとき1回だけ「ペタッ」と押される演出(Reduce motion で省略)。今月は、月末まで全日が埋まるまで出さない。
- データ: 日付は `e.date`(**今日の1枚として貼った日**。決定表「ステッカー帳のページ」と同じ定義)をそのまま日単位で使う。**日付の定義を変えない**。日付→日の対応はローカル時間(`T12:00:00` で組み立てている既存流儀に合わせ、境界でずれないこと)。Rust の新コマンドが必要なら最小限にする(既存の `book_page(year, month)` で足りるはず)。

### 受け入れ条件
- List に月/年の見出し・タブが出ない。Calendar では月見出しとめくりが出る。
- List ⇄ Calendar を切り替えても、選択中のステッカー(`BK.sel`)・詳細パネル・Peel / Gift / Stick の動作が壊れない。
- 日付ごとの集計・COMPLETE 判定・曜日オフセット(1日が何曜日か、閏年の2月、31日の月)は**純関数にして `tests/` にテストを追加**する。
- 最小ウィンドウ幅(Studio / Desk 両シェル)で、グリッドがはみ出さない。
- 既存の golden スクリーンショット比較ツール(`docs/port-spec/compare/README.md`)の手順があれば、List の見た目が意図した変更の範囲に収まるか確認し、差分を説明する。

## 5. 小さな直し(素材の開封)

`src/app/js/ceremony.js` の `openMaterial`(今日の素材の開封):

1. **「Pull it out.」が引き出し後も残る**。`onPull` で引き出しが確定した**瞬間**に、ヒントを「Tilt it to catch the light.」に切り替える(今はカードが飛んでいくアニメーションの後で切り替わるため、その間ずっと「Pull it out.」が出ている)。同じ文言は Pack(`cer.hint("Pull it out.")` の別の箇所)にもある。**Pack / Gift のスリーブでも同じ症状なら同じ直し**を入れ、違うなら触らず報告する。
2. **ウィンドウが低いと、引き出したカードが見出し(ヒント)に重なる**。引き出したカードの最終位置とスケール(いま `dy = stage の高さ × .42`、`k = 300 / 幅`)を、**ヒント文とその下の情報(`rv-info`)の両方と重ならない範囲に収まるよう、ステージの高さから計算**する(高さが足りないときはスケールを下げる)。最小ウィンドウ高さで重ならないことを確認する。

### 受け入れ条件
- 引き出した直後から、ヒントは「Tilt it to catch the light.」のみ。
- 最小ウィンドウ高さ(Studio / Desk)で、カード・ヒント・Keep it ボタンが重ならない。
- 位置とスケールの計算は純関数にして、`tests/` に境界値のテストを追加する。
