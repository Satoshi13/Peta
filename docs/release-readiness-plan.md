## 1. いちばん重要: 仮の公式鍵

- **何が問題か**: `official_keys.rs` の `k1` は RFC 8032 のテスト用の公開鍵で、対応する秘密鍵も RFC に載っている。だから、この鍵を受け入れる版では、**誰でも「公式」の配布ファイル(PETAEVNT: 素材などを配るイベント)を作れる**。オーナーの秘密鍵が漏れたわけではない。
- **影響の範囲**: 公式鍵を使うのは公式イベント(`events.rs`)だけ。公式カタログは廃止したので、パック・Gift・台帳には関係ない。
- **対応(推奨)**:
  1. **通常版・ベータ版でk1を信用しない**（対応済み）。コードの位置1byteを変えないため配列slot 0は残し、信頼する公開鍵だけをNoneにした。テスト・DeveloperだけRFC鍵を使う。
  2. 公式イベントを配るときに、本物の鍵を作る。秘密鍵は**オーナーの手元だけ**に置き(リポジトリ・Worker・アプリには入れない)、公開鍵を `k2` として足す。鍵を作る手順は `server-howto.md` に書く。
- **いつ**: ベータ前(友達が改造した「公式」ファイルで素材を増やせるため)。

## 3. オーナーが決めること・やること

### 3.1 配布のしかた(ベータ前に決める)

| 決めること | 選択肢 | 推奨 |
|---|---|---|
| どこで配るか | (a) 自分のサイト・R2 から notarize した .dmg を直接配る / (b) Mac App Store | **(a)**。今のアプリは macOS の非公開 API を使うので、App Store は審査に通らない可能性が高い |
| 署名の名義 | 個人の Apple Developer / 法人の Apple Developer | 下の注意を読んで決める |
| 更新 | (a) 手動で新しい .app を渡す / (b) Tauri Updater(署名つきの自動更新) | **ベータは (a)、公開前に (b)** |

- **名前が出ることについて**: Developer ID で署名すると、証明書に「Developer ID Application: 名義」が入り、アプリを調べれば誰でも読める。**個人登録なら名義は法的氏名**になる。本名を出したくなければ、法人(D-U-N-S 番号が要る)で登録するしかない。コードから名前を消すこととは別の問題。
- 手元の .app は署名の検証に失敗している(adhoc 署名)。配る .app は、Developer ID で署名 → 公証 → `codesign --verify --deep --strict` と `spctl -a -vv` が通ることを確かめてから渡す。手順は `distribution-howto.md` に足す。
- Apple Developer Program は年 99 ドル。

### 3.2 法律面(公開前。専門家と)

| やること | 内容 |
|---|---|
| 運営者・問い合わせ窓口 | プライバシーポリシーの運営者名・連絡先(専用のメールアドレスを作る)・施行日を埋める。通信販売の表示は**お金を取らない間は不要**だが、名前を完全に伏せたまま運営できるとは考えない |
| プライバシーポリシーの確定 | 下書き(S2・S3 の追記を含む)を専門家に見てもらう。Cloudflare(外国にある第三者)の扱いは個人情報保護委員会のガイドラインに沿って整理する |
| 利用規約 | まだない。ユーザーが作った画像の権利(作った人のもの、Peta は運ぶだけ)、禁止事項、通報と削除、退会、免責。Market と Gift があるので公開前に必須 |
| 届出 | 「無料の間は不要」は**方針で、確定した法的判断ではない**。Gift・Market の運用を説明して、**管轄の総合通信局に確認**する |
| 素材の権利 | 同梱のアート(Codex が作ったもの・見本ステッカー・参考画像から描き直したもの)の利用条件を一覧にする。フォントの OFL は同梱済み |

### 3.3 運用(公開前)

- 本番の準備: `peta-reports-prod` と `peta-market-prod` を非公開で作成 → D1 の migration → deploy → `REPORT_WEBHOOK` を設定 → 使用量の通知を設定。
- 通報の担当と確認の周期、運営が鍵を止める・解除する手順を dev で一度試す。
- `wrangler.jsonc` の account ID・D1 ID は秘密ではないが、ソースを公開するなら設定の見本と実際の設定を分ける。Git の作者情報(名前・メール)も、公開するなら確かめる。
