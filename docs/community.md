## 命名・所有者

ステッカー名と作者の表示名は別物。ステッカー名は作者が決める。ローカル原本は最初のGift作成まで変更でき、以降は固定。Giftにはその名前を同梱し、受取側には名前の更新権限がない。過去の名前なしGiftは名前なしのまま開ける。

共有サービスでも最初のGift/公開の際に名前を固定する。サーバーが認証された作者IDと固定状態を管理し、APIに渡された `author` や役割を信用しない。表示名の変更は過去の印字済み `creatorName` を書き換えない。

ファイルGiftの作者名・ステッカー名は来歴の表示用で、本人確認済みという意味ではない。ファイルの名前やローカルIDだけを根拠に、第三者の作品を作者本人の投稿として登録してはいけない。初回の原本登録・所有権の付与・既存ライブラリの取り込みはサービス実装時の独立した処理にする。

## 接続時のルール（実装案）

| 対象 | ルール |
|---|---|
| ログイン | 認証プロバイダーの外部ブラウザ＋PKCEを利用。バックエンドがトークンを検証しアカウントIDを確定。プロバイダーは未決 |
| 認証情報 | macOS Keychain等のOS資格情報ストアで保持。JS・SQLite・ログに長期トークンを保存しない。ログアウトで破棄 |
| Follow | 認証されたユーザーの関係をサーバーに保存。PUT/DELETEは冪等。自己Followを拒否。オフライン時は未送信と分かる表示にする |
| 共有投稿 | 原本の所有者だけ投稿可能。完成PNG/プレビューだけ送る。元写真と端末のファイルパスを公開データへ含めない |
| 投稿の再送 | `operationId` をアカウントごとに一意に記録し、通信切断後の再送で投稿を重複作成しない |
| 審査 | 新規投稿は `pending`。公開カタログは `published` だけ取得。`hidden` / `rejected` は公開画像も取得できなくする |
| モデレーター | サーバーで付与した役割だけ有効。状態遷移は `expectedRevision` を確認し、変更者・理由・日時・変更前後を監査ログに残す |
| 通報 | 投稿への通報。通報者の個人情報は公開しない。送信回数を制限 |
| 削除・停止 | 公開停止を全端末へ通知し、一覧・画像のキャッシュを無効化。既に受け取った個人のコピーの扱いは別途決める |
| エラー | 401=ログインが必要、403=権限不足、409=競合、429=再試行待ち、503/通信失敗=未送信。成功したように表示しない |

## 私有ライブラリの同期（設計案・まだAPI未実装）

端末内ライブラリと公開Marketは別のアクセス権で扱う。ログインだけで過去の写真や全ステッカーを自動アップロードしない。最初に対象を選ぶ移行画面を用意する。

同期はアカウント単位の変更カーソル＋リビジョン＋操作IDで行い、成功応答を受けてからローカルの送信済み位置を進める。オフライン操作は送信待ちとして保存。削除はtombstoneにし、復帰した端末から復活しないようにする。409の古いリビジョンは再取得して解消し、無条件の上書きはしない。受取Gift/Packの名前変更は同期側でも拒否する。

完成PNG・マスク・来歴を同期対象とする案。元写真を同期するかは容量と利用目的を含めて別途決める。ディスプレイUUIDと貼付座標は端末固有なので、他のPCのモニターへ自動で適用しない。

1日1枚のルールと素材在庫を複数端末で共有するかは未決。共有する場合はサーバーの原子的な予約・確定処理が必要。既存の「端末のローカル0時」をそのまま同期すると同じ日に複数枚を確定できるため、ルール決定後にDaily専用のAPIを追加する。今回の草案には同期とDailyのエンドポイントを含めていない。
