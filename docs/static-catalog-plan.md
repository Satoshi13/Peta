# 静的カタログ(Cloudflare)方針メモ

決定日: 2026-10-05(オーナー)。**方針の記録であり、実装は未着手**。実装するときは別の依頼書(Codex 用)を起こす。
関連: Gift の受信箱は [`gift-inbox-plan.md`](gift-inbox-plan.md)(同じ Cloudflare アカウント・ドメインを使う)。
前提の仕様: [`codex-signed-distribution-prompt.md`](codex-signed-distribution-prompt.md)(署名・作者パック `PETAPACK`)、[`distribution-howto.md`](distribution-howto.md)(オーナー向けの鍵と配り方)、[`signed-distribution-report.md`](signed-distribution-report.md)(実装済みの範囲)。

## 決めたこと

1. **Market に「公式が選んだ作者パックの一覧」を出す**。**サーバーのプログラムは作らず、アカウントも作らない**。置くのは静的ファイルだけ。
2. **置き場所は Cloudflare**:
   - **Cloudflare Pages**: カタログ(`index.json`)と、必要なら簡単な案内ページ。
   - **Cloudflare R2**: パックの実体(`PETAPACK` ファイル)とプレビュー画像。
   - **ドメインは Cloudflare の DNS で管理**する(登録元の移管は必須ではない)。
3. **信頼の鎖は2段**(どちらもアプリ側で**オフライン検証**できる):
   - **カタログの署名 = 公式の鍵**(`official_keys.rs`)。「公式がこの一覧を認めた」。
   - **パックの署名 = 作者の端末鍵**(`PETAPACK`、実装済み)。「この作者が作った、改ざんされていない」。
   - カタログの各項目に、パック本体の **SHA-256** と作者の公開鍵(指紋)を入れ、**ダウンロード後にハッシュ → 作者の署名の順に検証**してから取り込む。
4. **掲載は公式が審査して追加する**(作者が自分で勝手に置く形ではない)。作者はパックファイル(`PETAPACK`)を公式へ送り、公式が確認してカタログに載せる。作者が直接アップロードできる形は、サーバーと認証が要るので**今回やらない**。
5. **お金は扱わない**。当面は**無料パックのみ**。有料化・決済は [`port-spec/open-questions.md`](port-spec/open-questions.md) の O2 のまま未決(Web決済+サーバー、または Mac App Store のアプリ内課金)。
6. **取り込み後の挙動は既存どおり**: 受け取ったパックは棚に並び、開封は何度でも(Market のパックはいつでも)。カタログから外しても、**インストール済みの端末のパックは消えない**。

## コスト(2026-10 時点の見積もり。正確な料金は公式で確認)

| 項目 | 目安 |
|---|---|
| Cloudflare Pages | 無料(転送量・リクエスト無制限。ビルド月500回、1ファイル 25MiB まで) |
| Cloudflare R2 | 保存 10GB まで無料、超過は 1GB あたり月 $0.015。読み込み月 1,000万回まで無料。**転送量は無料** |
| ドメイン | 既存のドメイン(お名前.com)の更新料のみ |
| 想定 | 数百パック・数千ユーザーでも**月 0〜数百円** |

R2 は無料枠の範囲でも**支払い方法(カード)の登録が必要**。

## カタログの形(叩き台。実装時に確定)

```
https://catalog.<domain>/v1/index.json        … カタログ本体(署名つき)
https://packs.<domain>/<packId>/<version>.peta … パックの実体(R2、独自ドメインで公開)
https://packs.<domain>/<packId>/preview.png    … プレビュー(最大3枚。残りは「?」)
```

```json
{
  "format": 1,
  "issuedAt": "2026-10-05T12:00:00Z",
  "entries": [
    {
      "packId": "nao-desk-doodles",
      "version": 1,
      "title": "Desk Doodles",
      "author": "Nao",
      "authorKey": "<base64 公開鍵>",
      "count": 8,
      "price": "free",
      "size": 4200000,
      "sha256": "<パックファイルのハッシュ>",
      "file": "nao-desk-doodles/1.peta",
      "previews": ["nao-desk-doodles/preview-1.png"],
      "blurb": "…"
    }
  ],
  "signer": { "kind": "official", "keyId": "k1" },
  "signature": "<base64 Ed25519>"
}
```

- カタログ全体を公式鍵で署名する。**署名が通らない・古い形式(`format` が未知)の場合は無視**し、「アップデートしてください」を表示。
- **取り下し**はカタログから項目を消すだけ(インストール済みは消えない)。**危険な作者の取り消し**は、公式イベント `revoke`(実装済み)か、カタログに `blockedKeys` を足す案を実装時に検討する。

## アプリ側の実装(将来の依頼に入れること)

- Market の Packs タブを開いたときだけ `index.json` を取得(**常時ポーリングしない**)。ETag / If-Modified-Since でキャッシュし、**オフラインなら前回のカタログ**か、既存の同梱パックだけを表示。
- ダウンロードは**ユーザーの操作(Get)のあと**。サイズ上限(1パック 24MB、既存の `PETAPACK` の上限どおり)と、ハッシュ → 署名 → PNG 検証の順は変えない。失敗時の文言を用意し、**途中失敗で何も取り込まない**(既存のトランザクション)。
- 取得先の URL は定数 1か所にまとめる(**置き場所を差し替えてもアプリのロジックは変わらない**)。開発用に上書きできる設定を持つ。
- 通信するのは**カタログとパックの取得だけ**。分析・トラッキング・ユーザー識別は入れない。ただし**リクエスト元の IP は Cloudflare に見える**ので、プライバシーの説明に1行書く。
- DB は**既存の V8 の表(`packs` / 配布 Pack の項目)を使う**。必要になれば別途 V9 を設計する。

## 守ること・できないこと

- **配布数の制限、取り消し、同じパックの転送防止はできない**(署名の限界。仕様書・コメントに既に明記)。
- **作者の本人確認はしない**。署名の鍵が同じ=同じ作者、までしか言えない(初回に信頼)。公式が審査して載せることで補う。
- ダウンロード数など**利用状況は取らない**(Cloudflare のアクセス解析はサイト側の集計のみ)。
- 公開の置き場所なので、**カタログとパックのファイルは誰でも取得できる**。非公開のものは置かない。

## オーナーの作業チェックリスト(上から順に)

1. [ ] **公式の署名鍵を本物にする**(`docs/distribution-howto.md` §2)。いまの `official_keys.rs` の `k1` は**開発用の仮の公開鍵**で、`TODO(owner)` が残っている。**配布版を出す前に必ず入れ替える**(出荷後は、鍵の入れ替えに別の手順が要る)。秘密鍵はパスワードマネージャーとオフラインの2か所にバックアップ。
2. [ ] **Cloudflare のアカウントを作る**(無料、2段階認証を有効に)。
3. [ ] **ドメインを Cloudflare に追加する**(Free プラン)。**移管ではなく、ネームサーバーを Cloudflare に向けるだけ**でよい(登録はお名前.com のまま)。お名前.com で DNSSEC を使っていれば先に無効にする。既存のメールやサイトがあれば、DNS レコードの移し忘れに注意。
4. [ ] サブドメインを決める(例: `catalog.` と `packs.`)。
5. [ ] R2 を有効化(カード登録)→ バケットを作り、`packs.<domain>` で公開。
6. [ ] Pages のプロジェクトを作り、`catalog.<domain>` を割り当てる(中身は後で。Codex の実装と、署名ツール `peta-pass` の拡張が先)。

## 未決

- 作者がパックを**公式へ送る方法**(メール、フォーム、GitHub の Issue など)。
- 掲載の**審査基準**(著作権、不適切な画像、サイズ、枚数)と取り下しの運用。
- カタログに載った無料パックの**作者名の表示**(`author` を信じず、鍵の指紋を併記する既存方針を踏襲)。
- 有料化の方法(O2)。**Cloudflare を使う場合でも、決済は別のサービスが必要**。
- 作者が自分で出品できる形(アップロード、認証、審査の自動化)は、**サーバーとアカウントが要るので別フェーズ**。
